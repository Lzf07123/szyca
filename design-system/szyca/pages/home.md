# 首页页面覆盖规则

- 仅在首页、精确指针设备（`pointer: fine` + `hover: hover`）启用 10px 青色自定义指针；指针使用约 0.18 的插值延迟，悬停链接、按钮和表单控件时放大至 2.2 倍。触屏设备与 `prefers-reduced-motion` 保留系统指针。
- Hero 分为前景、中景和背景三层：前景文案移动最快，中景终端与轨道次之，背景网格与照片最慢。桌面最大位移保持克制；≤820px 位移强度降至 42%，reduced-motion 下完全关闭。
- 首页首屏短标题（3–16 字）可使用字符扰动定格：前 180ms 显示随机字符，随后从左到右逐字恢复，整段不超过 900ms。视觉字符必须对读屏隐藏，标题以完整的 `aria-label` 提供正确文本；长标题与 reduced-motion 直接显示原文。

- 页面结构由 Section 插件实例顺序决定；默认内容仍为 Hero → `$ whoami` 介绍带 → 活动类型 → 核心模块 → 页脚，抽奖开启时增加紧凑事件信号条。
- Hero 左侧使用 `> boot nebula_os ... [OK] ▊`、渐变主标题、一个主 CTA、一个幽灵 CTA 与三项系统统计。
- Hero 右侧使用玻璃终端、代码对象和静态轨道标记；背景照片只作低透明度纹理。
- `$ whoami → 关于我们` 使用一条紧凑玻璃介绍带；活动类型作为独立插件区块展示，不依赖介绍区块的兄弟关系。
- `$ ls ./modules` 聚合 `module-card` 插件；默认呈现答题中心、实时排行、加入我们三张卡片，同类插件重复添加时按实例顺序追加卡片。
- 每张模块卡使用 `[01]`–`[03]` 编号、中英混排标题、线性图标和 `OPEN MODULE` 操作语义。
- 抽奖开启时渲染 `#lottery` 事件条，使用紫色低透明信号底，不得挤压三卡主结构。
- 桌面临界以下保持自然换行；820px 起模块卡改为单列，超过三个实例时自动换行。
- 页脚以 `EOF — 感谢阅读到底部` 收尾。
