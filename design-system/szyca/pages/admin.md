# 后台工作台页面覆盖规则

- 后台沿用公共站的深空玻璃、56px 网格、等宽标签和细线语言，形成同一产品系统。
- 后台保留公共页眉中的品牌 Logo 作为返回官网入口，但隐藏公开站导航选项，避免前台业务菜单与后台导航混用。
- 顶部为紧凑控制台标题、身份、现场答题状态与退出操作。
- 桌面使用按“现场运营 / 内容维护 / 系统治理”分组的左侧导航；≤960px 使用单行“当前功能 + 展开导航”，不得把全部菜单常驻在首屏。
- 概览在统计卡之前显示“现在该做什么”，只列出当前权限允许进入的现场、题库、站点与活动入口。
- 概览首屏同时提供成绩导出快捷操作；该操作按 `scores.read` 显示，不依赖 `quiz.operate`。
- 概览随后显示四张真实统计卡，增幅只与上一次 10 秒刷新快照比较。
- 柱状图必须使用真实用户、参与、在线、题库和影像数量；环形图使用参与/注册转化率。
- 运行表至少覆盖数据库、Redis、答题状态、内存、协程和运行时长。
- 终端日志使用运行状态以及当前账号有权限读取的审计事件，不生成虚假趋势。
- 图表不是唯一信息源：每个图表必须同时提供数值、标签或可读文本摘要。
- 操作成功提示在视口固定位置显示并在 4.5 秒后消失；错误提示持续显示直到手动关闭；页面级读取失败必须提供可见原因与重试按钮。
- 不可逆或会阻断现场流程的操作使用危险色，并与保存、刷新等常规操作在视觉和空间上分离。
- 首页编排按运营语义展示区块：默认折叠，摘要同时显示区块类型、前台标题、启用状态和当前公开状态；展开后只显示该类型前台实际使用的字段。
- 区块排序使用上移/下移，不暴露原始 `sort` 数字；随其他区块合并展示的内容需要明确说明其生效位置。
- 模块开关与首页编排分别维护未保存状态和保存按钮，任何一侧保存都不得覆盖另一侧尚未保存的修改。
- ≤820px 统计卡两列；≤620px 图表、运行表和终端日志单列，页面本身不得横向溢出。
