# 后台工作台页面覆盖规则

- 后台沿用公共站的深空玻璃、56px 网格、等宽标签和细线语言，形成同一产品系统。
- 后台工作区最大宽度统一为 1240px；概览、现场控制、内容维护、系统治理等功能页的内容面均占满同一内容列，不继承公开页 720px 卡片上限；仅登录表单允许收窄。
- 单行下拉框统一使用内部控制箭头并预留右侧安全内边距，箭头不得贴边或越出控件边框。
- 高度差异明显的辅助工具卡应通栏放置，主要内容卡再组成等高双列，禁止自动网格留下大块空洞。
- 自动网格同一行的卡片必须等高，以底边对齐；需要自然高度时改用独立列流，不得混用。
- 筛选区优先使用通栏搜索框加双列条件；成对字段共享行基线，长示例放入占位符，避免标签异常换行。
- 抽奖等多段工作区使用后台内容区的中等级标题，不得复用营销页的大标题尺度。
- 后台保留公共页眉中的品牌 Logo 作为返回官网入口，但隐藏公开站导航选项，避免前台业务菜单与后台导航混用。
- 顶部为紧凑控制台标题、身份、现场答题状态与退出操作。
- 桌面使用按“现场运营 / 内容维护 / 系统治理”分组的左侧导航；≤960px 使用单行“当前功能 + 展开导航”，不得把全部菜单常驻在首屏。
- 概览首屏只显示一个“下一项操作”主焦点，其余当前权限允许的入口收敛为次级操作链接。
- 概览首屏同时提供成绩导出快捷操作；该操作按 `scores.read` 显示，不依赖 `quiz.operate`。
- 主焦点之后显示四张紧凑统计卡，不再使用大面积数据看板卡片；增幅只与上一次 10 秒刷新快照比较。
- 柱状图、参与转化、运行表和终端日志默认折叠在“详细运行数据”中，只有用户主动展开时才加载审计日志。
- 柱状图必须使用真实用户、参与、在线、题库和影像数量；环形图使用参与/注册转化率。
- 运行表至少覆盖数据库、Redis、答题状态、内存、协程和运行时长。
- 终端日志使用运行状态以及当前账号有权限读取的审计事件，不生成虚假趋势。
- 图表不是唯一信息源：每个图表必须同时提供数值、标签或可读文本摘要。
- 操作成功提示在视口固定位置显示并在 4.5 秒后消失；错误提示持续显示直到手动关闭；页面级读取失败必须提供可见原因与重试按钮。
- 不可逆或会阻断现场流程的操作使用危险色，并与保存、刷新等常规操作在视觉和空间上分离。
- 首页编排按运营语义展示区块：默认折叠，摘要同时显示插件名称、实例序号、前台标题、启用状态和当前公开状态；展开后只显示插件 Manifest 实际声明的字段。
- 首页编排通过“新增区块”选择 Section 插件；同一插件可重复创建实例，删除先进入待删除状态，允许撤销，保存时与新增、排序和内容修改一次提交。
- 活动影像实例展开后提供真实上传区、缩略图、图片说明、排序和删除操作；未保存的新实例显示“先保存编排”的只读说明。
- 区块排序使用上移/下移，不暴露原始 `sort` 数字；随其他区块合并展示的内容需要明确说明其生效位置。
- 模块开关与首页编排分别维护未保存状态和保存按钮，任何一侧保存都不得覆盖另一侧尚未保存的修改。
- ≤820px 统计卡两列；≤620px 图表、运行表和终端日志单列，页面本身不得横向溢出。
