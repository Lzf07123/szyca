# 功能模块开发契约

> 版本：1
> 目标：主体只负责网站框架与组合，主体外的业务能力以模块注册接入。

## 1. 两层扩展点

本项目有两个不同层级，不能混用：

| 层级 | 解决的问题 | 示例 |
|---|---|---|
| Section 插件 | 首页某一区块如何展示、配置和排序 | Hero、介绍、活动、抽奖入口、图集 |
| 功能模块 | 一个完整业务能力拥有哪些页面、API、权限、数据和依赖 | 答题、排行榜、抽奖、加入我们 |

Section 插件只负责业务模块在首页的呈现入口，不拥有答题轮次、抽奖库存或参与者会话。功能模块可以引用 Section 插件，但不能把业务逻辑写进 Section Manifest。

## 2. 主体边界

主体保留：

- React 站壳、公共布局、导航、页脚、错误页和懒加载框架；
- 首页与 Section 插件运行时；
- 站点内容、品牌、背景、二维码和功能开关；
- 管理后台壳、登录会话、CSRF、角色权限和审计；
- 媒体所有权、数据库迁移、健康检查和通用 HTTP 中间件；
- 模块契约、注册表和组合入口。

主体不直接实现：

- 答题轮次、作答、成绩和排行榜业务；
- 抽奖活动、奖品、抽取和领取业务；
- 加入页面和扫描二维码后的业务页面；
- 业务模块自己的页面细节、API handler 和领域查询。

## 3. 模块所有权

一个功能模块至少拥有：

1. 稳定的模块 key；
2. 可选的功能开关 key、展示名称和导航贡献；
3. 自己的前端路由与懒加载页面；
4. 自己的后端 API 注册器；
5. 自己的领域服务与数据表；
6. 自己的权限、审计语义和测试。

模块不得依赖主体页面的内部 state，也不得让主体反向 import 模块页面实现。

## 4. 后端注册契约

业务模块先在后端 Manifest 注册能力和导航元数据，再由 HTTP 组合层注册路由：

```text
appmodule.Manifest
  -> site 公开导航 / footer / feature 白名单
  -> httpapi API module registry
  -> module route registrar
  -> domain service
```

约束：

- 模块 key 与 feature key 必须稳定、唯一；
- 公开路径必须显式声明，不能由页面文件位置推断；
- 路由注册器只处理协议适配，业务仍归领域 service；
- 后台写接口必须经过 `access` 和 `audit`；
- 模块间只通过公开只读接口或领域事件协作，不跨模块直接写表。

## 5. 前端注册契约

前端模块 Manifest 声明：

- `key` 与展示名称；
- 可选的 `feature`；
- 路由 path、懒加载 Component；
- 是否受功能开关约束；
- 是否使用全屏布局。

组合层根据 registry 生成路由：

```text
app shell
  ├── core route: /
  ├── core route: /admin
  └── registered module routes
        ├── /join
        ├── /quiz + /result
        ├── /lottery
        └── /screen (fullscreen)
```

主体不能在 `App.tsx` 中逐个硬编码模块页面；新增模块只修改模块实现和 registry。

## 6. 依赖方向

允许：

```text
app composition -> module registry -> module implementation
module page -> shared UI / API client / own module contract
section renderer -> shared UI / public section data
```

禁止：

```text
core layout -> quiz internal state
lottery service -> quiz table direct write
section plugin -> lottery inventory query
module A -> module B page component
```

## 7. 新增模块步骤

1. 在后端 `appmodule` 注册模块 key、feature、公开路径和导航信息。
2. 在对应领域包实现 service、数据所有权和测试。
3. 新建后端 route registrar 并加入 API module registry。
4. 在前端 `modules` 目录实现模块 Manifest 与懒加载页面。
5. 在前端 module registry 注册，不修改站壳主体。
6. 如需首页入口，再单独注册 Section 插件。
7. 补充功能开关关闭、权限拒绝、直接 URL 访问和懒加载分包测试。

## 8. 模块下线

- 关闭 feature：隐藏导航和首页入口，公开 API 返回 `404 feature_disabled`。
- 移除前端实现：该模块路由不注册，不加载对应 chunk。
- 保留数据库表：不因模块下线自动删数据。
- 直接访问旧 URL：返回统一未开放页或 404，由模块 Manifest 决定。
