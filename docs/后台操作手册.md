# szyca 后台操作手册

## 1. 登录

1. 打开 `https://<站点域名>/admin`。
2. 输入首次部署时由 `ADMIN_USERNAME` / `ADMIN_PASSWORD` 创建的 owner。
3. 登录成功后使用 HttpOnly Cookie；浏览器存储中不会保存密码或后台 token。

生产环境必须：

- `ADMIN_COOKIE_SECURE=true`
- 使用 HTTPS
- `LEGACY_ADMIN_TOKEN_ENABLED=false`

## 2. 角色与菜单

| 角色 | 可见菜单 |
|---|---|
| owner | 全部 |
| content_editor | 概览、站点内容、媒体与外观 |
| event_operator | 概览、现场控制、抽奖、媒体只读 |
| data_viewer | 概览、题库只读、站点只读、成绩导出、审计 |

菜单隐藏只改善体验；越权请求仍由服务端返回 403。

## 3. 首页发布

“站点内容”可以：

1. 开关 `quiz / lottery / join / screen` 四个公开模块。
2. 点击“新增区块”，选择任意 Section 插件；同一类型可以重复添加，每个实例都以草稿加入页面末尾并自动展开。
3. 展开区块后使用“上移 / 下移”调整页面位置，或使用“删除区块”移除内容。
4. 删除在保存前只进入待删除列表，可点击“撤销删除”；保存后才会从数据库和公开端移除。
5. 区块默认折叠；摘要会显示插件、实例序号、启用状态和当前公开状态，展开后只出现该插件 Manifest 声明的字段。
6. 展开“活动影像”实例后可直接批量上传图片、编辑图片说明、上移/下移和删除图片；新实例需先保存编排，再上传图片。
7. 在“发布与定时”中设置草稿/发布/归档，以及可选的开始和结束时间。
8. 模块开关与首页编排独立保存，一侧保存不会覆盖另一侧未保存的修改。

规则：

- 不存储任意 HTML。
- CTA 只允许站内路径。
- 同一 Section 插件可存在多个实例，以实例 ID 区分；是否允许重复及最大数量由插件 Manifest 控制。
- 模块卡的标题、链接和排序会同步生成公开页眉选项；同一链接只显示首个入口。
- 插件字段、默认值和校验规则由后端 Manifest 提供；前端无法把未知字段或任意 HTML 写入数据库。
- 每个活动影像实例最多 4 张图片，单张不超过 10MB；删除图片或整个图集 Section 后，只有未被其他资源引用的文件才会从磁盘清理。
- 关闭模块后，导航、对应首页区块、公开路由和 API 同步失效。
- 保存后无需重新构建前端。

## 4. 抽奖准备

1. 在“抽奖”中保持模块总开关关闭，先完成需要开放的子模式配置。
2. 号码开奖模式可新建草稿场次，设置起始/结束号码、显示位宽，以及每个中奖等级的名称和中奖人数。
3. 单场总中奖人数不超过 100；等级按列表从上到下依次开奖，同一号码不会跨等级重复。
4. 确认配置后点击“上线大屏”，上线后号码范围、位宽和等级配置会锁定。
5. 个人抽取模式可继续使用旧活动、资格、奖品库存和领取流程；两种模式可以分别开关。
6. 在“站点内容”编排抽奖 Section，再开启模块总开关。
7. 在大屏确认待机/开奖状态，并在后台至少测试一次开奖推送。

## 5. 活动运营

- 号码开奖：后台只显示下一个待开等级；确认后一次性生成该等级中奖号码，并按号码顺序逐号推送大屏揭晓。
- 开奖结果提交后不可撤回或原地重抽；误操作时应归档场次并新建场次。
- 全部等级开完后，大屏保留本场分级总榜，直到管理员归档或上线下一场。
- 同一时间最多一个号码场次处于“大屏上线”；上线第二场前必须先归档当前场次。
- 归档的场次可在后台查看等级、开奖时间、操作员和中奖号码，并可导出 CSV。
- 个人抽取：暂停会阻止新抽取但保留数据；恢复受活动时间窗口约束；结束保留领取和导出。
- 模块总开关关闭优先于两个子模式；号码大屏幕和个人抽取子开关分别限制各自公开接口。

## 6. 领取核销

1. 在“抽奖记录”找到状态为“待领取”的记录。
2. 核对参与者昵称与奖品。
3. 线下交付后点击“核销领取”。
4. 服务端记录领取时间和管理员账号；重复核销返回冲突。

## 7. 媒体管理

- Logo、页脚图标、背景和二维码会写入媒体台账。
- “使用中”的文件不能直接删除。
- 先替换或清空所有引用，再删除文件。
- 同一文件被多个资源引用时会显示多个引用标签。

## 8. 账号管理

- owner 可创建四个固定角色。
- 停用账号会立即删除其现有会话。
- 不能停用当前登录账号。
- 至少保留一个启用中的 owner。

## 9. 审计排查

审计记录包含：

- 管理员账号、动作和资源；
- 请求 ID、IP 和时间；
- 脱敏后的 before/after 摘要。

密码、token、Cookie、CSRF 和授权头不会写入审计。

## 10. 活动后

1. 关闭抽奖模块总开关。
2. 导出抽奖 CSV。
3. 完成剩余领取核销。
4. 备份 `szyca_data`。
5. 记录异常请求 ID、错误率和延迟。
