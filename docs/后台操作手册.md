# szyca 后台操作手册

## 1. 登录

1. 打开 `https://<站点域名>/admin`。
2. 输入首次部署时由 `ADMIN_USERNAME` / `ADMIN_PASSWORD` 创建的 owner。
3. 登录成功后使用 HttpOnly Cookie；浏览器存储中不会保存密码或后台 token。

生产环境必须：

- `ADMIN_COOKIE_SECURE=true`
- 使用 HTTPS
- `LEGACY_ADMIN_TOKEN_ENABLED=false`

## 2. 角色与菜单

| 角色 | 可见菜单 |
|---|---|
| owner | 全部 |
| content_editor | 概览、站点内容、媒体与外观 |
| event_operator | 概览、现场控制、抽奖、媒体只读 |
| data_viewer | 概览、题库只读、站点只读、成绩导出、审计 |

菜单隐藏只改善体验；越权请求仍由服务端返回 403。

## 3. 首页发布

“站点内容”可以：

1. 开关 `quiz / lottery / join / screen` 四个公开模块。
2. 在“首页内容编排”中展开区块，使用“上移 / 下移”调整页面位置。
3. 区块默认折叠；摘要会显示启用状态和当前公开状态，展开后只出现该类型前台实际使用的字段。
4. 在“发布与定时”中设置草稿/发布/归档，以及可选的开始和结束时间。
5. 模块开关与首页编排独立保存，一侧保存不会覆盖另一侧未保存的修改。

规则：

- 不存储任意 HTML。
- CTA 只允许站内路径。
- 关闭模块后，导航、对应首页区块、公开路由和 API 同步失效。
- 保存后无需重新构建前端。

## 4. 抽奖准备

1. 在“抽奖”中保持总开关关闭，先完成活动配置。
2. 新建活动，设置资格、时间、未中奖权重和奖品库存。
3. 状态先保持草稿；完成测试后改为进行中。
4. 在“站点内容”启用抽奖 Section。
5. 最后开启抽奖总开关。
6. 测试一名符合资格的用户完成抽取与现场核销。

## 5. 活动运营

- 暂停：立即阻止新抽取，但保留数据。
- 恢复：只有活动仍在时间窗口内才可抽取。
- 结束：保留抽奖记录、领取状态和导出。
- 总开关关闭优先于活动状态。
- 奖品已有中奖记录时不能删除。

## 6. 领取核销

1. 在“抽奖记录”找到状态为“待领取”的记录。
2. 核对参与者昵称与奖品。
3. 线下交付后点击“核销领取”。
4. 服务端记录领取时间和管理员账号；重复核销返回冲突。

## 7. 媒体管理

- Logo、页脚图标、背景和二维码会写入媒体台账。
- “使用中”的文件不能直接删除。
- 先替换或清空所有引用，再删除文件。
- 同一文件被多个资源引用时会显示多个引用标签。

## 8. 账号管理

- owner 可创建四个固定角色。
- 停用账号会立即删除其现有会话。
- 不能停用当前登录账号。
- 至少保留一个启用中的 owner。

## 9. 审计排查

审计记录包含：

- 管理员账号、动作和资源；
- 请求 ID、IP 和时间；
- 脱敏后的 before/after 摘要。

密码、token、Cookie、CSRF 和授权头不会写入审计。

## 10. 活动后

1. 关闭抽奖总开关。
2. 导出抽奖 CSV。
3. 完成剩余领取核销。
4. 备份 `szyca_data`。
5. 记录异常请求 ID、错误率和延迟。
