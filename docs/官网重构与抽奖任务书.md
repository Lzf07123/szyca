# szyca 官网化重构、精细后台与集成抽奖任务书

> 文档版本：v1.0  
> 编制日期：2026-11-23  
> 项目：szyca（计算机协会招新答题系统）  
> 适用基线：`ba010bb` 之后的 `main`  
> 文档状态：开发与 Docker 验收完成；目标 Linux/正式域名上线待实际环境执行
>
> 验收记录：`docs/验收报告.md`

## 0. 会话结论摘要

1. 现有系统适合继续采用**模块化单体**，不拆微服务，不改变单容器、单 PostgreSQL、单 Redis 的部署形态。
2. 首页视觉、粒子、照片带、Logo 自适应、二维码、答题、排行、WS 和现有回归可以复用。
3. 当前代码属于技术分层，而不是功能模块：HTTP、Service 和 Store 均覆盖多个业务域，不能直接持续叠加官网和抽奖。
4. 当前单口令管理不支持精细权限。任何抽奖运营能力开放前，必须先完成管理员身份、角色权限和审计。
5. 扩表前必须先建立版本化迁移；抽奖不能写入 `quiz_state`，必须作为独立领域模块。
6. 推荐顺序为：模块与迁移底座 → 站点骨架与首页 Section → 后台 2.0 → 抽奖 MVP → 全链路验收与灰度上线。
7. 总工作量按单人开发估算约 10–14 个工作日，每阶段独立成分支、独立验收、可独立回滚。

## 1. 任务目标

### 1.1 建设目标

- 将现有招新答题站升级为可持续扩展的协会官网。
- 首页采用后台可配置的 Typed Section，支持后续增加活动、资讯、FAQ、赞助商等模块。
- 后台从单口令升级为账号、角色、权限、发布与审计体系。
- 新增集成抽奖模块，由后台控制总开关、活动生命周期、奖品、库存和领取。
- 保持现有答题、排行、大屏、二维码、外观配置和部署方式不回归。

### 1.2 成功定义

- 后续新增官网功能时，只需增加一个功能模块，不修改无关模块内部实现。
- 关闭抽奖后，首页入口、导航入口、公开接口和抽取行为同时停止。
- 非授权管理员无法执行管理动作，所有后台写操作可追溯到具体账号。
- 抽奖不超发、不重复，服务端随机不可由客户端控制。
- 现有 API、页面和数据完成兼容迁移，不出现数据丢失或现场答题故障。

## 2. 范围

### 2.1 本期范围

- 版本化数据库迁移与模块组合层。
- 公共站点配置、导航、页脚、页面和首页 Section。
- 公共布局、首页模块化、路由懒加载和页面元信息。
- 参与者身份模块边界整理。
- 答题模块边界整理与现有能力保留。
- 媒体资源记录、引用关系和删除保护。
- 管理员账号、会话、固定角色、操作权限和审计日志。
- 功能开关：`quiz`、`lottery`、`join`、`screen` 等模块的显示与 API 可用性。
- 抽奖活动、奖品、库存、抽取、结果、领取和导出。
- 对应单测、集成测试、浏览器验收、并发测试、迁移和回滚验证。

### 2.2 本期不做

- 不拆微服务、不拆独立数据库、不引入消息队列。
- 不做自由拖拽建站、任意 HTML 编辑或复杂页面搭建器。
- 不做多租户、通用会员体系或线上支付。
- 不做高价值奖品的实名认证、物流、核销终端或第三方营销平台对接。
- 不改变现有单人答题身份模型；设备指纹仍只作为弱身份校验。
- 不删除答题、排行榜和大屏核心能力。

## 4. 架构原则

### 4.1 模块化单体

每个功能模块同时拥有自己的路由、页面、API、权限、数据和测试。模块间只通过公开服务接口、只读查询接口或领域事件协作。

```text
app composition
├── site        公开站点、页面、Section、导航、页脚
├── identity    参与者身份与 token
├── quiz        题库、轮次、作答、排行
├── lottery     活动、奖品、抽取、领取
├── media       图片与媒体引用
├── realtime    WebSocket、公告、特效
├── access      管理员、会话、角色、权限
├── audit       管理操作审计
└── platform    配置、迁移、功能开关、通用 HTTP
```

### 4.2 依赖规则

- `site` 只读取公开功能开关和站点内容，不直接访问题库表。
- `lottery` 通过 `ParticipantReader` 和 `QuizEligibilityReader` 获取资格，不写入答题状态。
- `quiz` 只保存参与者 ID，不承担后台账号与站点展示。
- `media` 是所有上传文件的唯一所有者，其他模块只保存媒体引用。
- 所有后台写接口先经过 `access` 权限判断，再由目标模块执行业务，并由 `audit` 记录。
- 组合层 `httpapi` 只注册模块和通用中间件，不直接实现业务。

### 4.3 后台角色与权限矩阵

| 权限域 | owner | content_editor | event_operator | data_viewer |
|---|---|---|---|---|
| 站点读取 | 是 | 是 | 是 | 是 |
| 站点编辑/发布 | 是 | 是 | 否 | 否 |
| 媒体读取 | 是 | 是 | 是 | 否 |
| 媒体上传/删除 | 是 | 是 | 否 | 否 |
| 答题运营控制 | 是 | 否 | 是 | 否 |
| 题库读写 | 是 | 否 | 否 | 只读 |
| 成绩读取/导出 | 是 | 否 | 否 | 是 |
| 抽奖配置 | 是 | 否 | 是 | 否 |
| 抽奖领取核销 | 是 | 否 | 是 | 否 |
| 管理员与审计 | 是 | 否 | 否 | 审计只读 |

菜单显示依据角色生成，但所有接口必须由服务端执行权限判断。不能以“前端隐藏了按钮”代替授权。

### 4.4 数据库边界

第一阶段允许共用现有 `store` 和数据库连接，但模块必须声明自己的数据所有权。不得新增跨模块的大 JOIN 业务查询。

建议表所有权：

| 模块 | 数据表 |
|---|---|
| `site` | `site_settings`、`site_pages`、`home_sections`、`footer_settings`、`qrcodes` |
| `identity` | `users` |
| `quiz` | `questions`、`attempts`、`round_questions`、`quiz_state` |
| `lottery` | `lottery_campaigns`、`lottery_prizes`、`lottery_draws` |
| `media` | `media_assets` |
| `access` | `admin_accounts`、`admin_sessions`、`admin_roles` |
| `audit` | `admin_audit_logs` |
| `platform` | `feature_flags`、`schema_migrations` |

## 5. 接口契约

### 5.1 公开接口

| 方法 | 路径 | 说明 |
|---|---|---|
| GET | `/api/site` | 聚合品牌、导航、页脚、公开模块开关和首页 Section |
| GET | `/api/content/pages/{slug}` | 可选：公开内容页 |
| GET | `/api/quiz/*` | 保留现有答题接口 |
| GET | `/api/lottery/campaign` | 当前活动公开信息和用户可见状态 |
| POST | `/api/lottery/draw` | 带用户 token 和 `request_id` 的抽取 |
| GET | `/api/lottery/me` | 当前用户的抽奖结果与领取状态 |

`/api/config`、`/api/qrcode`、`/api/backgrounds` 等在迁移期保留兼容，新前端完成切换后再决定下线路由。

### 5.2 后台接口分区

```text
/api/admin/site/*
/api/admin/media/*
/api/admin/quiz/*
/api/admin/lottery/*
/api/admin/access/*
/api/admin/audit/*
```

后台鉴权要求：

- 登录会话使用 HttpOnly、Secure、SameSite Cookie。
- 写接口执行权限检查，并校验 Origin/CSRF 策略。
- 旧 `X-Admin-Token` 只作为迁移期兼容入口，完成切换后移除。
- CORS 不得继续对任意 Origin 开放后台 Cookie 请求。

### 5.3 抽奖接口语义

- 达到全局开关关闭时：公开接口返回 `404 feature_disabled`，后台仍可按权限配置但不可开放。
- 活动未开始或已结束时：页面可见状态，抽取返回 `409 campaign_not_active`。
- 用户不符合资格时：返回 `403 not_eligible`。
- 用户已抽取时：同一 `request_id` 返回原结果；不同请求返回 `409 already_drawn`。
- 库存不足或奖品异常时：返回确定结果，不产生负库存，不落半成品记录。

## 6. 数据模型要求

### 6.1 站点与功能开关

- `feature_flags(key, enabled, config, updated_by, updated_at)`
- `site_pages(id, slug, title, summary, body, status, seo, published_at, updated_by)`
- `home_sections(id, kind, enabled, sort, starts_at, ends_at, config, status, updated_by)`
- `media_assets(id, path, mime, width, height, checksum, created_by, created_at)`
- `media_refs(media_id, module, resource_type, resource_id, created_at)`：显式记录 Logo、二维码、背景、奖品图片等引用关系；被引用文件禁止直接删除。
- 站点 Section 的 `kind` 与 `config` 必须有后端类型校验，不接受任意 HTML。

### 6.2 后台权限与审计

- `admin_accounts(id, username, password_hash, role, disabled, created_at)`
- `admin_sessions(id, account_id, token_hash, expires_at, last_seen_at, ip, user_agent)`
- `admin_audit_logs(id, actor_id, action, resource_type, resource_id, before, after, request_id, ip, created_at)`
- 密码使用 Argon2id 或同等级安全哈希。
- `audit` 对敏感字段做脱敏，不记录密码、token、完整 Cookie。

### 6.3 抽奖

- `lottery_campaigns(id, name, status, starts_at, ends_at, eligibility, max_draws_per_user, enabled, created_by, updated_at)`
- `lottery_prizes(id, campaign_id, name, total, remaining, weight, enabled, sort)`
- `lottery_draws(id, campaign_id, user_id, prize_id, status, request_id, created_at, claimed_at, claimed_by)`
- `lottery_draws` 必须有 `(campaign_id, user_id)` 唯一约束和 `request_id` 唯一约束。
- 抽取必须在事务中完成资格校验、库存扣减、结果写入和审计。
- 随机源必须使用 Go `crypto/rand`，不得使用 `math/rand`。

## 8. 总体验收标准

### 8.1 功能验收

- [x] 首页品牌、导航、页脚、背景和首页 Section 全部来自统一站点配置。
- [x] 后台可以调整 Section 顺序、启停和定时发布，公开端无需重新构建即可生效。
- [x] `/quiz`、`/join`、`/screen`、`/result` 等旧链接行为保持兼容。
- [x] 关闭某个功能模块后，公开入口、导航入口、直接路由和 API 同时不可用。
- [x] 抽奖总开关与活动状态相互独立，任一条件不满足时不能抽取。
- [x] 符合资格的用户可以正常抽取，不符合资格、重复抽取和活动结束均返回明确错误。
- [x] 管理员可查看活动、奖品、库存、抽奖记录和领取状态。
- [x] 旧问答、排行榜、大屏和二维码功能不回归。

### 8.2 权限与安全验收

- [x] 数据库或日志中不存在明文管理员密码。
- [x] 后台页面不把管理员口令存入 `sessionStorage` 或 `localStorage`。
- [x] 生产环境的后台 Cookie 启用 `HttpOnly`、`Secure` 和 `SameSite`。
- [x] 未登录、会话过期、账号禁用和越权访问均返回正确拒绝结果。
- [x] `content_editor` 可编辑站点和媒体，但不能控制答题或抽奖；`event_operator` 不能导出成绩或修改站点；`data_viewer` 不能发起写操作。
- [x] 每个后台写操作生成一条可定位到管理员、资源、时间和请求 ID 的审计记录。
- [x] 同一来源连续登录失败达到阈值后返回 429，成功登录后按策略恢复。
- [x] CORS、Origin、CSRF 和可信 `X-Forwarded-For` 规则有自动化测试。
- [x] 媒体被多个对象引用时不能直接删除，引用解除后才允许回收。

### 8.3 数据与迁移验收

- [x] 从当前数据库快照执行迁移成功，重复启动不会重复执行已应用迁移。
- [x] 用户、题目、作答、轮次、排行、二维码、背景、页脚和 Logo 数量与内容无意外变化。
- [x] 迁移失败时不留下半迁移状态，服务启动失败信息可定位。
- [x] 新表、索引和唯一约束在空库与旧库升级两种路径均通过。
- [x] 备份、恢复和回滚在新旧版本之间演练成功。

### 8.4 抽奖公平性与一致性验收

- [x] 抽奖随机值由服务端使用 CSPRNG 生成。
- [x] 客户端篡改奖品、概率、用户 ID 或活动状态不能改变服务端结果。
- [x] 同 `request_id` 重试返回完全相同结果，不重复扣库存。
- [x] 同一活动同一用户并发提交多次只成功一次。
- [x] 100 个唯一用户并发抽奖时库存不为负，中奖数量等于库存扣减数量。
- [x] 奖品权重、资格条件、活动时间和暂停状态均以数据库事务内状态为准。
- [x] 抽取失败不产生无奖品的半成品记录。
- [x] 公开响应不包含奖品概率、其他用户结果或后台配置。

### 8.5 前端与体验验收

- [x] 320、390、768、1024、1280、1440px 视口无文档级横向溢出。
- [x] 键盘可以完成导航、首页主要入口、抽奖和后台关键表单。
- [x] 焦点样式可见，正文对比度达到 WCAG AA，主要点击目标不小于 44×44px。
- [x] `prefers-reduced-motion` 下关闭持续粒子、扫描和循环背景动画。
- [x] 公开主页、抽奖页和后台控制台无未处理异常，浏览器 console 0 error。
- [x] 首页只需一次 `/api/site` 即可获得品牌、导航、页脚、模块开关和 Section，不再由 Layout/Home/Footer 各自重复拉取。
- [x] 每个公开页面有唯一标题和描述；内容不存在时显示明确 404。
- [x] 站点配置接口失败时显示可用的静态降级首页，不出现整页白屏。

### 8.6 性能与稳定性验收

- [x] 现有答题全链路回归全部通过，400 VU 功能成功率 100%，HTTP 失败数为 0。

## 9. 发布与回滚条件

### 9.1 发布顺序

1. 部署模块底座和迁移，确认旧功能无回归。
2. 发布新站点 API 和首页模块，保留旧 API。
3. 发布后台账号、权限与审计，完成管理员账号迁移。

5. 后台创建测试活动和测试奖品，完成隔离环境全流程。
6. 设置活动时间并开启总开关，现场观察抽取成功率、库存、错误率和延迟。
7. 活动结束后关闭总开关，保留数据导出和领取核销。

### 9.2 回滚要求

- 每阶段可单独回滚到上一个 merge commit。
- 新表保持向后兼容，旧代码不得因新表存在而失败。
- 抽奖关闭不依赖代码回滚，必须由功能开关立即停止入口和抽奖 API。
- 迁移前必须备份 `szyca_data`；回滚前先导出抽奖和审计数据。
- 若后台新会话异常，临时恢复旧口令必须受时间窗口和环境开关限制，并在修复后轮换口令。

## 12. 风险与控制

| 风险 | 后果 | 控制措施 | 验收证据 |
|---|---|---|---|
| 无版本化迁移 | 半迁移、启动失败或数据损坏 | 版本表、advisory lock、事务化迁移、迁移前备份 | 空库/旧库升级与恢复报告 |
| 旧 API 过早移除 | 页面或外部缓存失效 | 兼容适配层、调用观察期、至少一轮全链路回归 | 兼容矩阵与请求日志 |
| 单口令后台继续存在 | 越权、误操作无法追责 | 先完成账号、权限、审计，再开放抽奖运营 | 权限负向测试和审计记录 |
| Cookie 会话与宽松 CORS 冲突 | 会话泄露或 CSRF | 同源部署、严格 Origin、CSRF 校验、Secure Cookie | 安全自动化测试 |
| `X-Forwarded-For` 可伪造 | 限流与审计 IP 失真 | 仅信任已知反代网段，入口层覆盖客户端伪造值 | 限流与 IP 记录测试 |
| 抽奖库存热点 | 超发、重复发奖或超时 | 行锁、唯一约束、幂等键、短事务、并发压测 | 并发库存与结果一致性报告 |
| 设备指纹可重置 | 重复参与抽奖 | 线下核销；高价值活动增加人工身份核验 | 规则说明与领取审计 |
| 媒体被多对象引用 | 替换或删除造成图片失效 | 显式引用表、删除保护、引用解除后回收 | 多引用删除测试 |
| 首页特效与资源阻塞 | 手机首屏慢或卡顿 | 路由懒加载、粒子按需、静态降级、减少动态 | 体积与首屏基线 |
| 一次合并全部重构 | 问题定位和回滚困难 | 分阶段分支、兼容开关、逐阶段 merge commit | 各阶段独立回滚记录 |
| 单实例限流状态丢失 | 服务重启后失败计数清零 | 当前单实例可接受；若扩容改用 Redis 共享限流 | 重启行为说明 |
