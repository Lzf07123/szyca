# szyca 部署与回滚手册

## 1. 生产前置

- Docker Engine + Docker Compose。
- 至少 1 GB 内存；数据全部位于 `szyca_data` 单卷。
- 外部反向代理终止 TLS。
- 外部代理透传：

```nginx
proxy_set_header Host $http_host;
proxy_set_header X-Real-IP $remote_addr;
proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
proxy_set_header X-Forwarded-Proto $scheme;
proxy_set_header X-Forwarded-Host $http_host;
proxy_set_header Upgrade $http_upgrade;
proxy_set_header Connection "upgrade";
```

## 2. 环境变量

```dotenv
ADMIN_USERNAME=owner
ADMIN_PASSWORD=<首次启动专用强口令>
ADMIN_COOKIE_SECURE=true
ADMIN_SESSION_HOURS=8
LEGACY_ADMIN_TOKEN_ENABLED=false
POSTGRES_PASSWORD=<数据库强口令>
WEB_PORT=8080
TRUSTED_PROXY_CIDRS=127.0.0.1/32,::1/128
SZYCA_IMAGE_REGISTRY=registry.example.com/
SZYCA_IMAGE=szyca:latest
SZYCA_PULL_POLICY=always
```

`ADMIN_PASSWORD` 只在创建首个 owner 时使用。账号已存在时重启不会覆盖密码。

## 3. 首次部署

1. 备份现状，即使为空卷也保留记录。
2. 配置 `.env`。
3. 拉取镜像：

```bash
docker compose -f deploy/docker-compose.yml pull
```

4. 启动：

```bash
docker compose -f deploy/docker-compose.yml up -d
```

5. 验证：

```bash
curl -fsS http://127.0.0.1:8080/healthz
curl -fsS http://127.0.0.1:8080/readyz
curl -fsS http://127.0.0.1:8080/api/site
```

6. owner 登录后台，创建其余角色账号并立即改强密码。
7. 保持抽奖总开关关闭，配置活动与奖品。

## 4. 数据备份

推荐整卷快照，覆盖 PostgreSQL、Redis AOF 和上传文件：

```bash
mkdir -p backup
docker run --rm \
  -v szyca_data:/data:ro \
  -v "$PWD/backup:/backup" \
  alpine:3.24 \
  tar -czf /backup/szyca-data-$(date +%Y%m%d-%H%M%S).tgz -C /data .
```

可额外生成逻辑数据库备份：

```bash
docker exec szyca env PGPASSWORD="$POSTGRES_PASSWORD" \
  pg_dump -h 127.0.0.1 -U szyca -d szyca -Fc \
  > backup/szyca-db.dump
```

备份后必须在新卷恢复并验证 `/readyz` 与关键表行数，不能只检查文件存在。

## 5. 恢复

恢复会覆盖目标卷，先确认目标不是生产卷或已经另存备份。

```bash
docker compose -f deploy/docker-compose.yml down
docker volume create szyca_data_restore
docker run --rm \
  -v szyca_data_restore:/data \
  -v "$PWD/backup:/backup:ro" \
  alpine:3.24 \
  tar -xzf /backup/szyca-data-YYYYMMDD-HHMMSS.tgz -C /data
```

使用临时 Compose project 指向恢复卷验证后，再切换正式卷。不要直接在半恢复卷上启动生产。

## 6. 迁移

启动时自动执行：

```text
schema_migrations
  -> advisory lock
  -> 校验已应用版本 SHA-256
  -> 按文件名顺序执行未应用版本
  -> DDL + 版本记录同事务提交
```

失败时：

1. 保留容器日志；
2. 不重复反复重启；
3. 从 `schema_migrations` 和日志确认最后成功版本；
4. 用备份恢复空库/旧库验证；
5. 修复迁移文件时不得修改已发布且已应用的版本，新增下一版本。

## 7. 发布顺序

0. 执行 `modulegen --check`、Go 测试、前端构建和浏览器验收。
1. 备份并在隔离栈执行迁移。
2. 部署新镜像，验证旧答题/排行/WS/二维码。
3. 验证 owner 与四种角色权限。
4. 保持 `lottery.enabled=false` 验证代码和后台表。
5. 配置测试活动，完成资格、抽取、库存、暂停、重放、领取。
6. 开启抽奖 Section 和总开关。
7. 现场观察错误率、P95/P99、库存和领取状态。
8. 活动结束先关闭总开关，再完成导出和核销。

## 8. 回滚

### 仅关闭抽奖

后台关闭总开关即可，无需回滚代码。入口、公开接口和抽取行为同时停止。

### 回滚应用镜像

1. 记录当前镜像 digest。
2. 将 `SZYCA_IMAGE` 切回上一阶段镜像。
3. `docker compose pull && up -d`。
4. 验证 `/readyz`、`/api/site`、答题和排行。
5. 新表保留；旧代码不得删除新表。

阶段回滚点：

| 阶段 | merge commit |
|---|---|
| 迁移与站点底座 | `052f846` |
| 官网首页 | `1ddad77` |
| 后台 RBAC | `8bc8c52` |
| 抽奖模块 | `1d91b6a` |

### 数据回滚

先导出抽奖与审计结果，再恢复备份卷。恢复后必须核对：

- 用户、题目、作答、轮次；
- 排行、二维码、背景、Logo、页脚；
- 抽奖库存、抽取记录、领取状态；
- `schema_migrations` 版本与校验和。

## 9. 灰度与观察

建议指标：

- `/api/site` P95 < 100ms；
- 抽奖 100 并发 P99 < 200ms；
- 抽奖成功率、资格拒绝率、库存不足率；
- 401/403/409/429；
- PostgreSQL 连接数和锁等待；
- 容器 CPU、内存、重启次数。

## 10. 安全

- 后台只在 HTTPS 同源使用。
- `TRUSTED_PROXY_CIDRS` 只配置实际反代网段。
- 禁止把数据库、Redis、后台密码或真实 token 写入记忆库、README、提交和日志。
- 旧口令入口完成迁移后永久关闭。
- 媒体删除前检查引用；抽奖奖品有中奖记录时禁止删除。
