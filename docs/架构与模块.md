# szyca 架构与模块

## 1. 运行形态

szyca 保持单镜像、单容器、单数据卷：

```text
Nginx :8080
  ├─ React 静态资源
  ├─ /api -> Go :8081
  └─ /ws  -> Go :8081
Go
  ├─ PostgreSQL :5432（容器回环）
  └─ Redis :6379（容器回环）
```

## 2. 业务模块

| 模块 | 职责 | 数据所有权 |
|---|---|---|
| `site` | 公开配置、页面、首页 Section、活动影像、品牌 | `site_pages/home_sections/gallery_images/feature_flags/site_settings/footer_settings/qrcodes/backgrounds` |
| `access` | 管理员、会话、固定角色、CSRF | `admin_accounts/admin_sessions/admin_roles` |
| `audit` | 管理写操作审计与脱敏 | `admin_audit_logs` |
| `media` | 资源台账、引用与删除保护 | `media_assets/media_refs` |
| `quiz` | 身份、答题、成绩、排行 | `users/questions/attempts/round_questions/quiz_state` |
| `lottery` | 活动、奖品、抽取、领取 | `lottery_campaigns/lottery_prizes/lottery_draws` |
| `platform` | 迁移与通用基础设施 | `schema_migrations` |
| `realtime` | WebSocket 与事件广播 | Redis Pub/Sub |

## 3. 依赖规则

- `site` 只读公开开关和站点数据。
- `lottery` 通过只读 `EligibilityReader` 获取答题资格，不写 `attempts` 或 `quiz_state`。
- 后台写接口先经过 `access`，再由目标模块执行业务，最后写入审计。
- `httpapi` 只做组合、中间件与协议适配。
- `media` 是文件引用事实的唯一来源，其他模块只保存 URL。
- 首页 Section 只通过编译期插件注册表扩展；`kind` 是插件 key，`id` 是实例身份。
- `gallery_images` 归 `site` 所有，文件与引用归 `media`；删除图片或 Section 后由媒体引用状态决定文件是否清理。

## 4. 首页 Section 插件

后端 `site` 维护 Section 插件 Manifest 注册表，负责插件 key、版本、标签、功能开关、实例数量限制、默认配置、字段 Schema 和安全校验。SQL 层不再保存固定 `kind` 白名单。

前端维护同名的渲染器/编辑器注册表。`block` 插件逐实例渲染；`module-card` 插件由模块布局组聚合。普通配置字段由 Manifest 自动生成表单，复杂交互可通过自定义 `Editor` 扩展。

插件缺失或版本不兼容时，公开端跳过未知实例，后台保留数据并提供删除能力，不自动清理。完整契约见 [Section插件开发.md](Section插件开发.md)。

## 5. 功能模块边界

主体只保留站壳、公共布局、首页 Section 运行时、后台治理、媒体、迁移和通用平台能力。答题、排行榜、抽奖、加入等完整业务能力通过功能模块 Manifest 注册。

每个模块必须声明公开路径、feature、导航贡献、前端懒加载路由和后端 API 注册器。`App.tsx` 与 `httpapi.Handler` 只执行 registry 组合，不直接引用模块页面实现。完整契约见 [功能模块开发.md](功能模块开发.md)。

## 6. 抽奖事务

```text
request_id 重放查询
  -> 读取当前活动
  -> 只读资格检查
  -> 事务内 FOR SHARE 固定活动状态
  -> 唯一用户/request_id 检查
  -> CSPRNG 加权选择
  -> 条件扣减库存
  -> 写抽奖记录
  -> 提交
```

多个不同用户不会互相串行锁定活动行；同一活动暂停会等待当前短事务完成。唯一约束兜住同用户并发，扣库存使用 `remaining > 0` 条件，失败时不产生负数或半成品。

## 7. 迁移与回滚

- `schema_migrations` 保存版本、SHA-256 和申请时间。
- 应用启动获取 PostgreSQL advisory lock。
- 每个版本在一个事务中执行 DDL 和版本写入。
- 已应用版本校验和不一致时拒绝启动。
- 新表对旧版本保持向后兼容；抽奖关闭不依赖代码回滚。

## 8. 前端结构

- `SiteProvider` 全站只请求一次 `/api/site`。
- `PublicLayout` 使用后端导航和页脚。
- 路由按页面懒加载，首页通过 Section 插件注册表逐实例渲染。
- 主体外的页面由功能模块 registry 注册，站壳不直接 import 模块页面。
- 管理后台按 capabilities 生成菜单和可写状态。
- 设计令牌位于 `frontend/src/index.css`，静态品牌文案位于 `frontend/src/brand.ts`。
