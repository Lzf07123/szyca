## 1. 运行形态

szyca 保持单镜像、单容器、单数据卷：

```text
Nginx :8080
  ├─ React 静态资源
  ├─ /api -> Go :8081
  └─ /ws  -> Go :8081

Go :8081
  ├─ PostgreSQL :5432（容器回环）
  └─ Redis :6379（容器回环）
```

模块在构建时进入同一个 Go 二进制和 React 产物，不提供运行期下载或远程升级。

## 3. 模块所有权

| 模块 | 职责 | 数据/运行时资源 |
|---|---|---|
| `site` core | 品牌、页面、功能开关、首页 Section、背景、页脚 | `site_pages/home_sections/feature_flags/site_settings/footer_settings/backgrounds` |
| `access` core | 管理员、会话、固定角色、CSRF | `admin_accounts/admin_sessions/admin_roles` |
| `audit` core | 后台写操作审计 | `admin_audit_logs` |
| `media` core | 文件台账、引用、删除保护 | `media_assets/media_refs` |
| `platform` core | 迁移与通用平台 | `schema_migrations` |
| `quiz` | 身份、题目、回合、作答、成绩、排行数据 | `users/questions/attempts/round_questions/quiz_state` |
| `lottery` | 活动、奖品、抽取、领取 | `lottery_campaigns/lottery_prizes/lottery_draws` |
| `join` | 加入页面、二维码 | `qrcodes` |
| `screen` | 排名 API、大屏、排行榜 Section | 无独立表 |
| `realtime` | 公告、特效、WebSocket | `announcements`、Redis Pub/Sub |
| `gallery` | 图集、图片排序、媒体引用 | `gallery_images` |

## 4. 编译与生成流水线

核心生成命令：

```bash
cd backend/core/modulecatalog
go generate
go run ../../../cmd/modulegen --check
```

输入：

- `modules/*/module.json`
- `modules/*/backend/migrations/*.sql`

输出：

- Go 模块元数据 catalog；
- Go 模块实现注册表；
- 合并后的迁移资源；
- TypeScript 模块 catalog；
- 前端 runtime registry；
- 前端模块样式导入顺序。

生成文件已提交，普通构建不需要执行生成器。生成器不是运行期发现机制，构建产物中的
模块集合由生成文件决定。

生成器拒绝：

- key 与目录不一致；
- 重复 key/feature/route/capability/admin tab/Section；
- 未注册 feature 或非法 Section layout；
- 缺失依赖或循环依赖；
- 未知固定角色；
- 缺少 `frontend/index.tsx`。

## 5. 后端构造与生命周期

启动顺序：

1. 加载配置。
2. 打开 PostgreSQL 连接池。
3. 执行 core 和模块迁移。
4. 构造 access/audit/media/rank/publish 等共享服务。
5. 初始化 core 站点默认值。
6. `moduleregistry.Build` 按依赖图构造模块 service。
7. `runtime.Start` 启动排行榜刷新、WebSocket 等后台任务。
8. 从 runtime 获取 `IdentityValidator`、`RealtimeRuntime`、Gallery/Join provider。
9. 使用 provider 构造 core site 服务。
10. 构造 HTTP Server，注册 core routes 和所有 `HTTPModule`。
11. 开始监听；关闭时先停止 HTTP，再 `runtime.Stop`。

模块构造顺序由 `requires` 决定。`Start/Ready/Stop` 遍历生成 catalog；因此模块
`Start` 只能依赖已构造的 service，不能假设依赖模块的 `Start` 已经执行。

## 6. 后端接口层次

### 6.1 Module

每个模块实现：

```go
func NewModule(contract.Dependencies) (contract.Module, error)
```

`Module` 暴露：

- manifest；
- 对其他模块可见的 service；
- migration；
- ready/start/stop。

### 6.2 HTTPModule

模块实现 `RegisterHTTP(mux, API)`，由生成 runtime 的模块列表统一注册。

`backend/core/httpapi` 提供：

- feature gate；
- 用户身份；
- 管理员认证、权限和审计；
- JSON 响应辅助；
- 上传、媒体附加、释放和引用检查；
- WebSocket token/origin 配置。

core HTTP 不 import 任何具体模块。

### 6.3 跨模块契约

常用接口：

- `IdentityValidator`：核心用户认证；
- `Readiness`：所有模块 readiness 聚合；
- `ConfigContributor`：`/api/config` 扩展；
- `OverviewContributor`：管理概览扩展；
- `ClientCounterProvider`：在线连接数；
- `AnnouncementReader`：旧配置兼容；
- `site.QrcodeProvider`：公开二维码；
- `site.GalleryProvider`：公开图集。

跨模块 provider 由 main 注入，core site 不查询模块表。

## 7. HTTP 请求路径

业务 API：

```text
Nginx
  -> HTTPModule.RegisterHTTP
  -> HTTP feature/permission middleware
  -> module handler
  -> module service
  -> module repository / core provider
```

规则：

- 公开 feature 关闭时返回 `404 feature_disabled`。
- 后台写请求先校验 HttpOnly session、Origin、CSRF 和 capability。
- 审计由 `Permission` wrapper 统一记录。
- 模块响应不得泄漏内部权重、token 或其他用户数据。

## 8. Config / Overview 组合

`/api/config`：

```text
core site data
  + modules.Config(ctx)
  -> merged JSON map
```

当前：

- site 提供 footer、logo、features；
- quiz 提供 title、quiz_state、question_seconds；
- realtime 提供 announcement。

`/api/admin/overview`：

```text
core runtime metrics
  + modules.Overview(ctx)
  -> merged JSON map
```

当前：

- core 提供 online、backgrounds、uptime、goroutine、memory；
- quiz 提供 users、attempts、participants、questions、DB/Redis 状态。

贡献 key 必须无冲突。模块缺失时对应字段消失，core 不保留模块私有查询。

## 9. 首页 Section

后端 Section registry 由 `modulecatalog.Sections()` 与 core Section 合并。
数据库实例通过 `home_sections.id` 标识，`kind + plugin_version` 选择前端实现。

前端两种布局：

- `block`：逐实例独立渲染；
- `module-card`：统一进入模块网格。

未知 key、版本不一致或插件缺失时：

- 公开端跳过；
- 后台仍显示数据和删除能力；
- 数据不会自动清理。

Hero/About/Activities 是 core Section；Quiz/Lottery/Join/Screen/Gallery 的
Section 来自对应模块。

## 10. 前端组合

```text
main.tsx
  -> SiteProvider(/api/site 单次请求)
  -> generated MODULE_RUNTIMES
  -> App router
       ├─ core Home/Admin
       └─ module lazy routes
```

模块 runtime 可以贡献：

- manifest；
- 懒加载页面路由；
- Section 插件；
- 后台面板；
- 模块 CSS。

后台：

- `module.json.admin_tabs` 决定标签和权限；
- `moduleRuntime.adminPanels` 决定实际组件；
- `Admin.tsx` 只提供登录、布局、权限判断和通用上下文。

首页：

- `Home.tsx` 只处理排序、Section 插件选择和模块网格布局；
- 不按 Quiz/Screen 等具体 key 插入特殊卡片。

## 11. 样式边界

- 设计令牌与公共外壳：`frontend/src/index.css`、`styles.css`、`cosmos.css`。
- 通用组件：`frontend/src/components`。
- 模块样式：`modules/<key>/frontend/styles.css`。
- 生成器按模块顺序输出 `module-styles.generated.ts`，在 core CSS 后加载。
- 模块不得依赖未声明的全局选择器优先级；共享组件必须通过 core 暴露。

## 12. 迁移

迁移来源：

- core 兼容迁移：`backend/core/platform/migrate/migrations/`
- 模块迁移：`modules/<key>/backend/migrations/`

启动时：

1. 获取 PostgreSQL advisory lock；
2. 建立 `schema_migrations`；
3. 合并 core 与模块迁移；
4. 校验已应用迁移 SHA-256；
5. 按版本名排序；
6. 每个迁移和版本记录在同一事务提交。

历史迁移文件名和内容不可修改。模块下线不删除表或迁移记录。

## 13. 测试结构

- 后端：service/repository、路由、权限、迁移和依赖图单测。
- 生成器：manifest 校验、重复项、循环依赖和 `--check` 漂移。
- 前端：严格 TypeScript + Vite 构建。
- 浏览器：模块 tests facet + 生成 Manifest 动态断言。
- Docker：实际镜像构建、`/readyz`、迁移和数据保留。

完整验证命令见 [README](../README.md)。

## 14. 已知边界

- 当前是编译期模块，不是运行期插件。
- `main` 仍负责选择 core 所需 provider，例如 Quiz identity、Realtime counter、
  Join/Gallery site provider。
- `site` 仍是 core 内容模块，不参与业务模块数组。
- 模块的精确 admin 子路由以 `routes.go` 为准，`module.json.routes` 是声明和
  校验元数据，不会自动生成 handler。
- 要实现独立发版、远程升级或多团队隔离，需要另行设计微前端、独立进程或沙箱插件。
