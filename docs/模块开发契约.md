# 模块开发契约

> 契约版本：2
>
> 更新：2026-11-24
>
> 适用范围：仓库根目录 `modules/<module-name>/`

本文是业务模块新增、修改和删除的权威契约。实现冲突时，以
`backend/contract/`、`modules/*/module.json` 和 `cmd/modulegen` 当前代码为准。
生成器、注册表和生命周期内部细节见 [模块系统实现.md](模块系统实现.md)。

## 1. 设计目标

模块采用编译期独立开发，不提供运行期下载、远程代码、WASM 或 Go `.so` 插件。

每个模块必须：

- 拥有稳定且唯一的模块 key；
- 拥有自己的后端 service、repository、HTTP routes、迁移和测试；
- 拥有自己的前端页面、后台面板、Section 和样式；
- 通过唯一权威 `module.json` 声明元数据、依赖和能力；
- 不通过修改 core 业务分支即可编译接入、关闭或移除；
- 与其他模块只通过公开接口、core provider 或业务事件协作。

两个扩展层不能混用：

| 层级 | 负责 | 不负责 |
|---|---|---|
| 功能模块 | 页面、API、service、表、权限、导航、后台 | 首页单个区块的配置字段 |
| Section 插件 | 首页区块 Manifest、Renderer、Editor、实例配置 | 业务库存、轮次和其他领域数据 |

## 2. 目录契约

```text
modules/<module-name>/
  module.json
  backend/
    module.go
    routes.go
    service.go
    repository.go          # 有持久化时
    types.go               # 有模块自有类型时
    seed.go                # 有初始化数据时
    migrations/
      <timestamp>_<name>.sql
    *_test.go
  frontend/
    index.tsx
    pages/
    admin/
    sections/
    types.ts
    styles.css
  tests/
    browser.mjs
```

约束：

- 目录名必须与 `module.json.key` 一致。
- 所有业务实现、模块迁移和模块测试必须位于该目录。
- `backend/core` 不得 import `modules/*`。
- `frontend/src` 不得直接 import 模块页面或后台组件。
- 模块不能 import 另一个模块的实现；跨模块接口由消费方或 core contract 定义。
- 模块业务表由模块自己写；其他模块只能读公开接口。

当前模块：

| key | feature | requires | 所有权 |
|---|---|---|---|
| `quiz` | `quiz` | 无 | 身份、题库、回合、作答、成绩、排行数据 |
| `lottery` | `lottery` | `quiz` | 活动、奖品、抽取、领取 |
| `join` | `join` | 无 | 加入页面、二维码、二维码后台 |
| `screen` | `screen` | `quiz`、`realtime` | 大屏、排名 API、排行榜 Section |
| `realtime` | 无公开 feature | `quiz` | WebSocket、公告、特效 |
| `gallery` | 无公开 feature | 无 | 图集数据、Section、图集编辑器 |

## 3. module.json

`module.json` 是唯一权威模块元数据，当前 `schema=1`。

### 3.1 顶层字段

| 字段 | 必填 | 说明 |
|---|---:|---|
| `schema` | 是 | 当前固定为 `1` |
| `key` | 是 | 唯一模块 key，必须与目录名一致 |
| `label` | 是 | 模块显示名称 |
| `feature` | 否 | 唯一功能开关 key；公开模块必须设置 |
| `path` | 否 | 公开入口，必须以 `/` 开头 |
| `nav_label` | 否 | 为空表示不贡献主导航 |
| `nav_order` | 否 | 主导航顺序 |
| `footer_label` | 否 | 为空表示不贡献页脚链接 |
| `public_metric` | 否 | 是否参与公开指标 |
| `feature_write_capability` | 有 feature 时必填 | 修改功能开关所需 capability |
| `requires` | 是 | 依赖模块 key，必须存在且无环 |
| `routes` | 是 | 页面与 API surface 的声明式元数据 |
| `capabilities` | 是 | 模块权限和固定角色默认授权 |
| `admin_tabs` | 是 | 模块新增的后台标签 |
| `admin_panels` | 是 | 向已有标签注入的面板 |
| `sections` | 是 | 模块拥有的首页 Section Manifest |

生成器会把空数组归一化为 `[]`。提交时仍建议显式写空数组。

### 3.2 routes

```json
{
  "path": "/example",
  "feature": "example",
  "fullscreen": false
}
```

- `path` 必须以 `/` 开头且全局唯一。
- `feature` 必须为空或等于模块 feature。
- `fullscreen` 只影响 React 站壳。
- `routes` 不生成 handler 或 Component。
- 实际后端路由必须在 `backend/routes.go` 的 `RegisterHTTP` 注册。
- 实际前端页面必须在 `frontend/index.tsx` 用 `lazy()` 注册。
- 三处路由必须同步，并由测试覆盖。

当前 `module.json.routes` 主要记录公开页面和主要 API surface；精确的后台子路由以
`routes.go` 为准。

### 3.3 capabilities

```json
{
  "key": "example.write",
  "label": "示例维护",
  "roles": ["content_editor"]
}
```

- capability key 全局唯一。
- `owner` 自动拥有 `*`，不需要在 `roles` 中声明。
- 固定角色只允许 `content_editor / event_operator / data_viewer`。
- 后台接口必须通过 `HTTP.Permission` 在服务端校验。
- 写操作由统一 wrapper 自动审计。

### 3.4 admin_tabs / admin_panels

`admin_tabs` 定义标签，`admin_panels` 定义组件插入点：

```json
{
  "admin_tabs": [
    {
      "key": "example",
      "label": "示例",
      "group": "content",
      "permission": "example.read",
      "order": 55
    }
  ],
  "admin_panels": [
    {
      "key": "example-panel",
      "tab": "example",
      "label": "示例面板",
      "permission": "example.read",
      "order": 10
    }
  ]
}
```

- `group` 当前使用 `operations / content / governance`。
- `admin_panels[].tab` 必须指向已注册标签。
- `frontend/index.tsx` 的 `moduleRuntime.adminPanels` 必须导出同 key 组件。
- `Admin.tsx` 不直接 import 模块 panel。

### 3.5 sections

```json
{
  "key": "example",
  "version": 1,
  "scope": "home",
  "layout": "module-card",
  "home_order": 60,
  "label": "示例入口",
  "description": "首页示例入口",
  "feature": "example",
  "repeatable": true,
  "max_instances": 0,
  "summary_field": "title",
  "default_config": {
    "title": "示例",
    "body": "示例说明",
    "action_to": "/example"
  },
  "fields": []
}
```

- `scope` 只允许 `home`。
- `layout` 只允许 `block / module-card`。
- `feature` 必须为空或引用已注册 feature。
- `max_instances=0` 表示不限制。
- `default_config` 必须符合 `fields`。
- `key@version` 全局唯一。
- `home_order` 只用于 fallback 和 E2E 默认预期；线上排序以 `home_sections.sort` 为准。

Section 的字段 Schema 和版本兼容见 [Section插件开发.md](Section插件开发.md)。

## 4. 后端契约

### 4.1 Module

权威接口位于 `backend/contract/module.go`：

```go
type Module interface {
	Manifest() Manifest
	Service() any
	Migrations() []Migration
	Ready(context.Context) error
	Start(context.Context) error
	Stop(context.Context) error
}
```

模块导出：

```go
func NewModule(deps contract.Dependencies) (contract.Module, error)
```

生命周期：

```text
Store.Open
  -> legacy + module migrations
  -> moduleregistry.Build
       -> 按 requires 拓扑构造模块
  -> Runtime.Start
  -> HTTP
  -> /readyz -> Runtime.Ready
  -> shutdown -> Runtime.Stop（逆序）
```

`Runtime.Build` 将 `Module.Service()` 写入 `deps.Module`，供后续模块通过窄接口消费。

约束：

- `Ready` 只检查本模块运行依赖。
- `Start` 不得假设依赖模块的 `Start` 已执行；只能假设其 service 已构造。
- `Stop` 必须可安全调用且不能删除业务数据。
- 模块迁移由生成器读取 `backend/migrations/*.sql`；`Migrations()` 目前统一返回 `nil`。

### 4.2 Dependencies

```go
type Dependencies struct {
	Context context.Context
	Core    map[string]any
	Module  map[string]any
}
```

共享 core key 当前包括：

| key | 类型 |
|---|---|
| `config` | `config.Config` |
| `store` | `*store.Store` |
| `rank` | `*rank.Rank` |
| `publish` | `*publish.Pub` |

模块必须显式校验依赖类型，缺失时返回错误，不能静默降级。

### 4.3 HTTPModule

```go
type HTTPModule interface {
	Module
	RegisterHTTP(*http.ServeMux, HTTP) error
}
```

`contract.HTTP` 提供：

| 能力 | 方法 |
|---|---|
| 功能开关 | `Feature / AnyFeature` |
| 用户身份 | `User / OptionalUser` |
| 管理员身份 | `Authenticated / Permission / Audit` |
| WebSocket | `ValidateToken / WSAllowedOrigins` |
| 在线数 | `OnlineCount` |
| 上传 | `SaveImage / RemoveFile` |
| 媒体引用 | `AttachMedia / ReleaseAndCleanup / AssertMediaUnreferenced` |

JSON、错误和 ID 解析使用 `backend/core/httpx`。

### 4.4 可选贡献接口

| 接口 | 用途 |
|---|---|
| `IdentityValidator` | token 验证 |
| `Readiness` | `/readyz` 聚合 |
| `ConfigContributor` | 合并 `/api/config` |
| `OverviewContributor` | 合并 `/api/admin/overview` |
| `ClientCounterProvider` | 在线连接数 |
| `AnnouncementReader` | 公告兼容读取 |
| `site.GalleryProvider` | `/api/site` 图集 |
| `site.QrcodeProvider` | `/api/site` 二维码 |

公共 map 贡献的 key 必须无冲突；core 不读取模块私有表。

## 5. 前端契约

每个模块必须导出：

```tsx
export const moduleRuntime = {
  manifest,
  sections: [SECTION_PLUGIN],
  adminPanels: [
    {
      key: 'example-panel',
      tab: 'example',
      permission: 'example.read',
      order: 10,
      Component: ExamplePanel,
    },
  ],
} satisfies AppModuleRuntime
```

类型位于 `frontend/src/modules/contract.ts`。

- 页面必须 `lazy()` 加载。
- route feature 必须与模块 feature 一致。
- internal 模块可以没有公开页面路由。
- 模块 Section 位于 `modules/<key>/frontend/sections/`。
- 模块后台组件接收 `AdminRuntimeContext`。
- 模块 CSS 位于 `modules/<key>/frontend/styles.css`。
- 模块不得直接编辑生成 registry。
- 浏览器测试可导出 `modules/<key>/tests/browser.mjs`。

`AdminRuntimeContext`：

```ts
interface AdminRuntimeContext {
  can(permission: string): boolean
  notify(message: string, error?: boolean): void
  reloadSite(): Promise<void>
  setQuizState(state: 'start' | 'stop'): void
}
```

## 6. 生成器

写入：

```bash
docker run --rm -v "$PWD:/src" -w /src golang:1.27-alpine \
  go run ./cmd/modulegen --write
```

检查：

```bash
docker run --rm -v "$PWD:/src" -w /src golang:1.27-alpine \
  go run ./cmd/modulegen --check
```

生成器读取：

- `modules/*/module.json`
- `modules/*/backend/migrations/*.sql`

生成物：

- Go module catalog；
- Go implementation registry；
- 合并迁移清单；
- TypeScript catalog；
- 前端 module registry；
- 模块样式导入顺序；
- 浏览器测试 Manifest。

生成文件提交到仓库并禁止手改。普通 Go/Vite 构建不依赖生成器。

校验包括：

- schema、目录/key；
- feature、route、capability、admin tab、admin panel、Section 唯一性；
- route/feature 关系；
- capability 角色；
- Section layout 和 feature；
- requires 存在性与依赖环；
- `frontend/index.tsx` 存在；
- 迁移版本全局唯一。

## 7. 数据与迁移

- 模块拥有自己的表和 SQL。
- 新迁移放 `modules/<key>/backend/migrations/`。
- 新迁移使用时间戳版本名。
- 已应用迁移禁止改名或改内容。
- core 历史兼容迁移保留在 `backend/core/platform/migrate/migrations/`。
- 迁移器合并 core 与模块迁移，按版本排序并检查全局唯一。
- 模块下线不自动删表、删迁移或删历史数据。

## 8. 新增模块

1. 创建 `modules/<key>/`。
2. 编写 `module.json`。
3. 实现后端 `NewModule`、service/repository、`RegisterHTTP`。
4. 实现前端 `moduleRuntime` 和懒加载页面。
5. 需要时增加 admin panel、Section、CSS。
6. 增加模块迁移。
7. 增加 Go 测试和 `tests/browser.mjs`。
8. 运行 modulegen `--write` 与 `--check`。
9. 运行 Go、前端和 Playwright 验证。

## 9. 修改与下线

修改：

- 只改本模块目录；共享契约变化需显式修改 `backend/contract`。
- Section Schema 变化必须提升版本并新增迁移。
- capability、feature、route 变化同步更新后台和测试。

下线：

1. 删除模块目录。
2. 有其他模块依赖时先处理 `requires`。
3. 重新生成注册表并构建。
4. 不删除历史迁移和数据表。
5. 旧前端 chunk 不再加载，旧 URL 不再注册。
6. 旧功能行、Section 和审计记录保留，只从公开响应过滤。

## 10. 测试门槛

- `go test ./...`
- `go vet ./...`
- `npm run build`
- `go run ./cmd/modulegen --check`
- feature 关闭返回 `404 feature_disabled`
- 无权限返回 403，写操作产生审计
- 生成 Manifest 驱动的 Playwright 路由、首页卡片、后台面板、axe 和响应式

## 11. 禁止事项

- 在 core 中 import `modules/*`。
- 模块直接 import 另一模块实现。
- 跨模块写表。
- 在 Home/App/Admin 中硬编码模块 key 分支。
- 手改 `*.generated.*`。
- 修改已应用迁移。
- 只隐藏前端按钮而跳过服务端授权。
- 为单模块复制 JSON、审计、上传、feature gate 中间件。

## 12. 非目标

- 运行期安装、卸载或远程升级；
- 独立模块二进制；
- 微前端；
- WASM、`.so` 或远程 JS；
- 多团队独立发版；
- 模块删除时自动清理数据库。
